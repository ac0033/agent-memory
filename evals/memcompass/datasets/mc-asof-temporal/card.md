# 数据卡：mc-asof-temporal（双时态与"截至某时"，K5）

> **v0.2（2026-09-14）**：45 条 / 130 道题；构造脚本 `build/build_at.py`，金标由双时态时间线重放器计算，星期与天数由代码算；计划类含 3 条“已完成”对照。全部未经人工核验。数据文件：examples.yaml（种子）+ migrated.yaml（如有）+ generated.yaml。

> 版本 0.1.0-draft（2026-09-13）｜状态：草稿，待用户审核｜**AML 兼容度最高的子集之一**：只用现行 Add/Search 与 aml-lme-aligned 契约。

| 项目 | 内容 |
|---|---|
| 子集名 / 前缀 | `mc-asof-temporal` / `at` |
| 测什么 | 能否分清"当时是什么状态"与"现在是什么状态"；能否分清**有效时间**（事情何时成立）与**记录时间**（我们何时得知）；能否处理事后追溯的更正、计划到期但没有确认、临时规则过期 |
| 能力 | 主：K5；辅：K4、K6、K11、K12 |
| AML 叶子 | C1 日期与间隔、C3 轨迹变化、D1 当前状态、D2 冲突消解；拟议扩展 N5"双时态与截至某时" |
| 轨道 | Q 问答轨（主）；可选 B 行为轨 |
| 种子 / 目标规模 | 5 条（13 题）/ 约 110 条用例、300 题 |
| 切分 | dev 60 / test 150 / held-out 90（按题计，同一用例的题在同一个切分里） |
| 许可建议 | CC BY 4.0 |

## 1. 动机

- **需求**：R2"时间顺序、先后与因果"、R4"最新、仍然有效"。框架 §5.1 中 K5 明确要求"截至某时"的状态，以及把到期的计划改写为已发生或已过期。agent-memory 没有双时态（P19 为"无"），layer2 也没有"截至某时"的用例（框架 §7.8）。
- **公开评测覆盖的是"最新状态"和"顺序"**：
  - LongMemEval 的 knowledge-update 与 temporal-reasoning、LoCoMo 的时间类问题、BEAM 的 knowledge update 与 event ordering（Kendall τ-b）；
  - MemoryAgentBench 的 FactConsolidation（"序号更大的事实覆盖旧事实"）。
- **公开集少有的**：
  - 问过去某个时点的状态（as-of）；
  - 区分"当时实际如何"与"当时我们以为如何"；
  - 追溯更正；
  - 计划过期而没有确认时应当弃答（`../../gap-analysis.md` G6）。

## 2. 类型与比例

| 类型 | 说明 | 比例 |
|---|---|---|
| `as_of_past` | 值有多个版本，问过去某日的值 | 25% |
| `retro_correction` | 用户事后说"其实从某日起就改了" | 20% |
| `event_vs_record_time` | 事件时间与得知时间不同，问其中一个或两个 | 15% |
| `plan_unconfirmed` | 有计划、没有完成记录，问"做完了吗" | 15% |
| `expired_validity` | 有有效期的临时规则，问现在或过去某日 | 15% |
| （对照）当前状态题 | 每条用例至少带一道"现在是什么"的题 | 约 10%，嵌在各用例中 |

## 3. 任务格式

| 字段 | 含义 |
|---|---|
| `probes[].reference_time` | 提问时刻；**必须同时写进 query 文本**，形如"今天是 YYYY-MM-DD。"（脚本 V14）。原因：AML 现行答题模板不传题目日期（见 `data/longmemeval-s/pipeline.py` 的 OPEN_ENDED_ANSWER_TEMPLATE） |
| `gold.labels.as_of` | 题目问的时点 |
| `gold.labels.time_axis` | valid（有效时间）/ record（记录时间）/ both |
| `gold.labels.retroactive` | 是否涉及追溯更正 |
| `gold.labels.answer_kind` | 如 `unknown_with_plan`：正确答案是"无法确认 + 给出计划信息" |
| `gold.labels.granularity / interval` | 时间粒度要求；是否需要算间隔 |

## 4. 示例

`examples.yaml` 共 5 条 13 题。完整展开两条：

**示例 A：at-0002 `retro_correction`**

| 部分 | 内容 |
|---|---|
| s1（2026-08-03 周一） | "站会每周一上午 10:00。" |
| s2（2026-09-10 周四） | "更正一下：站会其实从 8 月 31 日那周起就改到每周二上午 9:30 了，之前忘了跟你说。" |
| q1（有效时间） | "今天是 2026-09-10。9 月 7 日（周一）上午 10 点有站会吗？" → 没有；那周的站会在 9/8 周二 9:30 |
| q2（记录时间） | "今天是 2026-09-10。按 2026-09-05 那天我们手上的记录，站会被认为是什么时间？" → 每周一 10:00（当时还没收到更正） |
| q3（当前，对照） | "今天是 2026-09-10。现在站会是什么时间？" → 每周二 9:30 |

**示例 B：at-0004 `plan_unconfirmed`**

| 部分 | 内容 |
|---|---|
| s1（2026-09-02） | "数据库迁移定在 9 月 6 日（周日）凌晨做，王工执行。" |
| q1 | "今天是 2026-09-10。数据库迁移做完了吗？" → 无法确认：只有 9/6 凌晨由王工执行的计划，没有完成记录，建议向王工确认 |
| 陷阱 | 断言已完成；断言尚未进行 |

## 5. 构造流程

| 步骤 | 做法 | 参照 |
|---|---|---|
| ① 双时态时间线 | 为每个"实体.属性"生成一张表：值、有效区间 [from, to)、记录时刻 | 双时态数据库（valid time / transaction time）的通行做法〔推断〕；Zep 的时间知识图谱（框架附录） |
| ② **程序化金标** | as-of 查询由代码在表上计算：有效时间轴取"区间覆盖 t 的值"，记录时间轴取"记录时刻 ≤ t 的最新记录"；星期和间隔也由代码计算 | LoCoMo 的时间事件图；BEAM 的时间线 |
| ③ LLM 口语化 | 每条时间线事件扩写成对话，保留日期、数值等槽位（字符串校验） | BEAM |
| ④ 干扰 | 近似实体（同名属性、另一个项目）；同一实体的无关属性更新；相对时间表述（"上周一""下月初"） | LongMemEval 的时间感知题 |
| ⑤ 填充到目标长度 | 用自建填充会话把历史扩到 S 档（约 50 个会话，6 万 token）或 M 档（约 300 个会话，35 万 token）。**原因**：AML 正式评测 top_k=100，历史太短时检索形同全文，题目会失去区分度 | LongMemEval_S 与 _M；AML 文档中的 Top K 100 |
| ⑥ 人工核验 | test 与 held-out 100% 核验题面是否无歧义，重点核对星期和"那周"这类说法 | — |

## 6. 标注指南（要点）

1. 时间粒度严格对齐：金标是"日"就答到日，不能只答月份，也不能多给小时（与 AML/LoCoMo-Refined 评委的"strict granularity"规则一致）。
2. `time_axis: record` 的题，答案必须体现"当时的认知"，不能用后来的更正覆盖。
3. `unknown_with_plan` 类，只要断言已完成或未完成，就判错；弃答加计划信息判对。

## 7. 质量控制

| 检查 | 门槛 |
|---|---|
| 金标由重放器计算，与卡片一致 | 100% |
| 星期、间隔由脚本复核 | 100% |
| 评委对齐（二值） | 与人工一致率 ≥ 90%（参照 LongMemEval 评委 >97%、LoCoMo-Refined 86.33%） |
| 与公开集去重 | 与 LongMemEval、LoCoMo 题面的 8-gram 重合为 0 |

## 8. 指标

| 指标 | 定义 | 主/辅 |
|---|---|---|
| 准确率 | 二值判定（AML 式"包含 + 不矛盾 + 严格时间粒度"） | **主** |
| 分类型、分时间轴准确率 | 按 type × time_axis 分桶 | 辅 |
| 过时当现状率 | 当前题或 as-of 题中答出了被取代的值 | 辅（越低越好） |
| 双时态混淆率 | record 题答成 valid 值，或者反过来 | 辅 |
| 计划臆断率 | plan_unconfirmed 中断言已完成或未完成 | 辅 |

## 9. 基线

no-memory / full-context（S 档放得下时）/ naive-rag（按消息切块，稠密 + BM25）/ agent-memory-current / oracle（只给证据会话，参照 LongMemEval_oracle）。

## 10. 难度控制

版本数 2 / 4 / 6；干扰实体 0 / 3 / 10；历史规模 S / M；相对时间表述有 / 无；需要计算星期或间隔 有 / 无。

## 12. 已知局限

- 中文日期表述（"那周""下月初"）有地区习惯差异，需要人工核验。
- AML 的答题模板写着"If memories conflict, prefer the most recent supported memory"。这会系统性地压低 record 轴题目的得分，这恰好是本子集要暴露的现象，但在提案中需要说明。
- 需要英文平行版本时，要单独做本地化，而不是直译（〔待核〕AML 是否要求英文）。
