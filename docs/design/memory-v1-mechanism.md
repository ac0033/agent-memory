# 记忆机制说明（v1，证据锚定记忆）

> 读者：要理解或修改 `agent_memory/` 当前记忆机制的人。设计推导与实测记录在 `docs/research/memory-v1-design.md`；本文只说"现在是怎么工作的、为什么这样"。
> 分支：`feat/memory-v1`（2026-09-21 起）。上一代机制（v0.4，读取期 LLM 合成）在 `feat/memcompass-v02`，已弃用。

## 1. 一句话

**原文归档是唯一的值，记忆条目只是通向它的键和贴在它上面的注解；读取时只组织证据、不替答题者下结论；所有需要智能的工作放在写入期，而且只增不减。**

## 2. 为什么是这三条

用能力框架（`docs/research/agent-memory-capability-framework.md`，K1–K13）和它的成熟度标准（L2 = 显著优于朴素 RAG）反推出来的，不是从机制清单里挑的。三条原则各自对应一类实测过的失分：

| 原则 | 失分形态（实测） | 结论 |
|---|---|---|
| 一：证据是值，记忆是键和注解 | 蒸馏磨掉细节、条目自评"完整"，原话就不再出现，答题器无从补救（MemCompass ca/Q 80% vs 朴素 RAG 100%） | 载荷按构造包含原话，答题器看到的信息 ⊇ 朴素 RAG 给的 |
| 二：只组织，不裁决 | 读取期合成的"库里没有 X"排在载荷首位，否决了旁边的正确证据：赢 4 道弃答题、赔 7 道可答题（LongMemEval n=60） | 读路径零 LLM，不产出任何结论性内容；连"复述型"论断都不渲染 |
| 三：智能前移、只增不减 | 写入规则让蒸馏器把"上周五"替换成日期，评分要求原说法时就失分（LoCoMo 时间题） | 写入期产物永远是加在证据上的键与注解（绝对日期附在原说法后、线索词只进索引） |

## 3. 写入路径（`memory_add` → 归档 → 蒸馏 → 评价门 → 对账）

与 v0.2 相同的骨架，蒸馏产物多了两个字段、少了一类内容：

- `event_date`：这条记忆所述事件实际发生的日期。对话里的"昨天""三周前"按会话日期换算，**原说法保留、日期用括号附在其后**（规则 9）。
- `cues`：3–8 个线索词（实体、别名、上位类名词、活动类型）。只进索引文本（`MemoryEntry.index_text`），永不渲染。作用：换一种说法提问也能命中（K7）；散在多场会话的同类实例被同一个上位类词一起拉到场（K6）。
- 不再写总数：可计数的实例每个单独一条（规则 13）。蒸馏器只看得到当前一场会话，总数由读到全部记录的人去数。

原文归档的派生索引 `data/raw_index.db` 多了一张词级 FTS5 表 `raw_words`（unicode61），与 trigram 表 `raw_fts` 并存：英文按词做 BM25（与朴素 RAG 同口径），中文由 trigram 兜底。

## 4. 读路径（`MemoryService.recall` / `recall_items`，`long_term/retrieve/recall.py`）

只有这一条路；`memory_search`、`memory_context`、对外 Search 契约、全部评测 runner 都走它。零 LLM 调用。

```
记忆路：混合检索命中论断 ──┐  按证据位置 (source, session, line) 归并成"证据束"
原文路：混合检索命中原话 ──┘  两路各出名次，RRF 等权相加（不给任何一路加权）
      ↓
片段：同一场会话里相邻的命中行聚成一个片段（SEGMENT_GAP=2），片段按最好名次排序
      ↓
渲染：[日期] → 原话（命中行给全文，上下文行限长）→ notes:（只放注解）
```

**什么算注解、什么不渲染**（`_is_annotation`）：取代史（"此前：…"）、失效日期、非用户出处、换算出的事件日期，或者原话根本没到场——这些才渲染成 note。只是把在场原话复述一遍的论断**不渲染**（它已在检索里起过作用，渲染出来只会让答题器拿概括当事实；实测去掉后事实回忆 8/12 → 11/12）。常驻画像块同一规则：原话已在载荷里的画像条目不重复出现。

**体量纪律**：预算只约束注解，原文路命中的行一行不丢；载荷体量目标 ≤ 朴素 RAG 载荷的 1.15 倍。条数上限下并尾不截。

**载荷首条**（`header_text`）：读法（原话与 notes 不一致时以原话为准）、记录的时间跨度（问"多久以前"时答题的一方要知道记录截止到哪天）、一段静态的行为协议——问到用户自己过去的、且点名了记录里从未出现的具体人/物/事时说"没提过"；求建议的问题不在此列，照常给建议。三版措辞的取舍记录在设计稿 §9.2。

## 5. 不变量（有测试钉住，`tests/test_recall.py`）

- 载荷 ⊇ 只检索原文会给的：原文路每一条命中都在，命中行永不被上下文行或注解挤掉。
- 两路名次等权；同一束只计原文路最好名次。
- 读路径模块不依赖 LLM；渲染里不出现"不存在/共 N 个"这类合成结论。
- 复述型论断不渲染，带取代史的渲染；无原话时论断是唯一载体。
- 原文行过注入特征过滤；scope 在 SQL 层过滤。

## 6. 怎么验证（标准流程）

外部评测集只做验收，原则上每个只测一次；机制迭代靠自建验证集。某个外部集表现不佳时按顺序：框架是否涵盖该能力/指标 → 验证集是否覆盖 → 针对性提升（可查论文）→ 验证集通过 → 同一份已缓存的测试样本复测该板块 → 继续其余评测集。工具与数据布局见 `docs/research/benchmark-suite/README.md` §8。
