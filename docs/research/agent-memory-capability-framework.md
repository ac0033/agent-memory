# Agent Memory 能力维度、理想目标与评价体系

> 版本：v0.4 讨论稿（2026-09-13）
> 性质：优化 agent-memory 之前的"问题定义"文档。它回答三件事：好的 agent 记忆应具备哪些能力、做到什么程度、怎么度量。本文不含实施方案。
> 可信度标注：〔实测〕本机文件或代码已核实；〔官方〕官方文档；〔论文〕只读过摘要；〔综述〕综述或经典文献；〔逆向〕第三方逆向；〔推断〕作者推断；〔待核〕尚未核实；〔有争议〕文献结论不一致；〔已定〕用户已拍板。

## 摘要

- **需求**：从用户原话和修订意见中整理出 14 条需求（R1–R14，§1）。核心是四件事：
  - 当下的事全记得；
  - 专注当前任务，状态及时更新；
  - 在相关时刻被线索完整唤起；
  - 只记得大概时自己察觉，然后去查记录、找用户确认。
- **骨架**：三层记忆，各有侧重：短期记忆求全，工作记忆求专注与更新，长期记忆求精选且可被唤起。**整理贯穿三层，但时机不同**：T0 随时进行（工作记忆）→ T1 事件边界、T2 清醒休息（短期记忆）→ T3 睡眠（长期记忆）→ T4 提取时再巩固（三层都有）。每个时机都有神经科学证据支撑（§2）。
- **能力与机制分开**〔已定〕：
  - 评测对象是 **13 个能力维度（K1–K13）**，外加 3 个系统约束（Q1–Q3），见 §5。
  - 实现手段列为 **33 项机制（P01–P33）**。机制不直接打分，其价值用消融实验来证明（§5.3、§7.7）。
- **四项拍板结论**〔已定〕：
  - 能力与机制分离；
  - 原文复制归档，归档时对密钥做脱敏，只存本地、永久保留；
  - 新评测集由 agent 起草在 `docs/research/eval-drafts/`，用户审核后亲自迁入 `evals/`；
  - 主动联想和复述确认都**宁可少说**：主指标用 F0.5，偏重精确率。
- **现状**（§8，基于代码核实）：agent-memory 在治理、更新一致性、可靠性、跨会话续接上接近 L3。唤起（K7、K8）、完整性（K9、K10）、事件边界整理、归纳还处在 L0–L1。另外发现两个实测问题：
  - 归档是原样写入的，没有脱敏；
  - 归档只在会话收尾时发生，而 Claude Code 默认 30 天就清理本地会话记录。
- **遗忘请求**〔已定〕：用户明确要求删除某段内容时，作为 D1 的有条件例外，允许改写原文归档（§2.6）。
- **评测草稿已起草**：在 `docs/research/eval-drafts/` 下，包括专项二（K9、K10）、专项一（K7、K8）各 12 条种子用例，以及朴素 RAG 基线的设计，等待你审核后迁入 `evals/`。
- **v0.4.1 新增的两处实测发现**：
  - 现有 layer3 评测的评委判的是检索出来的上下文块里有没有目标事实，并不看 agent 的回答是否主动说出了关联。所以 91.67% 只能说明两条事实都被检索到了，不能证明 agent 会主动联想。

## 1. 需求

用户的原话有两层：

1. "为什么能如此准确地回忆我们之前沟通的内容，同时还能比较准确地把握时间顺序和先后关系……纯靠算力全记下来吗？"
2. "……不仅要跨对话有选择地获取记忆，还要获取到最新的，还要是主动地意识到现在要获取记忆了，还要建立起和当前对话的联系……在思考到某个地方的时候，联想到了之前的每段记忆，然后主动地提取出来并建立关联……可以降低大脑的认知负荷。"

修订意见又补充了四点：
- 线索唤起的关键在于"唤起得完整"；
- 察觉到记忆不完整时，要能去查、能确认；
- 短期记忆和工作记忆同样重要；
- 三层记忆都需要整理，只是时机不同。

| 编号 | 需求 | 主要涉及 |
|---|---|---|
| R1 | 准确回忆以前沟通过的内容 | 长期 |
| R2 | 把握时间顺序、先后与因果 | 长期 |
| R3 | 跨对话、有选择地取用 | 长期 → 工作 |
| R4 | 取到的内容是最新、仍然有效的 | 长期 |
| R5 | 自己意识到"现在该回忆了" | 工作 → 长期 |
| R6 | 把记忆和当前对话联系起来（联想） | 长期 → 工作 |
| R7 | 不背着全部记忆去思考，认知负荷低 | 工作 |
| R8 | 当前的思考和对话线索能唤起沉睡的记忆，而且唤起得完整；无论这段记忆平时能否主动想起，当下需要时都能被唤起并还原完整 | 长期 → 工作 |
| R9 | 可信：不编造，说明来源，区分证据和推断 | 全层 |
| R10 | 跨 agent 连续：Codex、Claude、kimi 等共用同一个"我" | 全层 |
| R11 | 察觉到自己记得不完整：①主动查阅保存的会话记录、任务表、纪要，把内容补全；②向用户复述自己的理解，请用户确认 | 工作，涉及全层 |
| R12 | 当下全记得：正在或刚刚发生的、与当前任务相关的内容完全记得 | 短期 |
| R13 | 专注当前任务并及时更新：清楚正在做的事的整体情况和状态，状态一变就更新 | 工作 |
| R14 | 经历要沉淀：重要的沉淀为可被唤起的长期记忆；不重要的也要完整保存，供以后检索、补全遗漏 | 短期 → 长期 |

## 2. 骨架：三层记忆，以及贯穿三层的整理

### 2.1 三层各自的侧重

| 层 | 侧重 | 内容 | 生命周期 | 对应人脑 | agent 中的载体 |
|---|---|---|---|---|---|
| 短期记忆 | **全** | 当前会话或事件的完整经过：用户原话、agent 回复、工具输入输出、文件改动 | 与会话一起滚动；会话结束后沉淀并归档 | 近期情景记忆：细节鲜活，但逐字细节衰减快（不是心理学里只维持几秒的"短时记忆"） | 上下文窗口 + 宿主的原生会话日志；**长期保存靠复制进归档**（§2.6） |
| 工作记忆 | **专注与更新** | 当前任务的全貌：目标、约束、计划、决策及理由、进度、待办、未决问题、关键变量 | 与任务同存亡；会话边界不等于任务边界；任务完成时先蒸馏，再清除 | 工作记忆与注意焦点（Baddeley、Cowan），加上"工作自我"的当前目标（Conway） | **按任务划分**〔已定〕：一个项目下可以有多个并行任务，各自一份状态；会话开头注入当前任务的状态，有多个时列出来供选择 |
| 长期记忆 | **精选、可唤起** | ①精选知识：情景、语义、程序、画像；②完整归档：历史原文，可检索、可回溯 | 跨会话、跨任务长期保存；离线巩固；按需遗忘 | 巩固后的要点、图式、技能，以及能被线索激活的细节痕迹 | Markdown 记忆层 + 索引 + 原文归档 |

工作记忆按任务划分，偏离了原设计文档 §2.2"项目只维护一份"的约定。理由是：同一个仓库里可能有多个任务、多个 agent 并行（比如 Codex 和 Claude 同时工作），只存一份会互相覆盖。

**专注状态最适合调用长期记忆**（用户的判断）。这与 Ericsson & Kintsch（1995）的"长时工作记忆"理论一致：专家在熟练执行任务时，靠任务中形成的提取结构来快速调用长期知识。所以工作记忆也是长期记忆的"提取上下文"：当前的目标、子问题和卡点，就是最好的检索线索。

### 2.2 整理贯穿三层，时机各不相同

神经科学的共识是：记忆在多个时间尺度上持续被加工，每个时间尺度主要作用于不同的记忆形态〔综述〕。

| 时机 | 时间尺度 | 人脑中发生的事（证据） | 主要作用的层 | agent 中对应的整理动作 | 触发条件 |
|---|---|---|---|---|---|
| **T0 随时** | 秒级，持续 | 注意刷新（TBRS 模型，Barrouillet & Camos）；**主动移除**：更新 = 移除过时项 + 编码新项，按条目进行，能释放容量、减少干扰（Ecker, Oberauer & Lewandowsky 2014；Oberauer 2018）；**门控**（PBWM，O'Reilly & Frank 2006）；**组块**（Miller 1956；Cowan 2001） | 工作记忆 | 状态一变就更新：用替换代替追加，主动删除过时和无关的内容，把完成的子任务压成一行结果，只放进与目标相关的内容 | 每轮对话；每次状态变化 |
| **T1 事件边界** | 秒到分钟 | 事件结束时海马活动出现高峰，**快速回放刚结束的整个事件**，把它绑定成一段情景；高峰的强度能预测以后回忆得好不好（Ben-Yakov & Dudai 2011；Baldassano et al. 2017；Silva et al. 2019）；人会按事件切分连续的经历（Zacks et al. 2007） | 短期 → 情景 | **边界打包**：把刚结束的事件打包成情节卡片（经过、结果、决策、时间、证据范围、线索），标注重要性；把关键状态抢救进工作记忆 | 子任务完成；话题切换；计划变更；上下文即将被压缩 |
| **T2 清醒休息** | 分钟到小时 | 学习后短暂的清醒休息就能增强长期记忆（Dewar et al. 2012）；休息时海马与皮层的相关性和记忆效果相关（Tambini, Ketz & Davachi 2010）；休息中出现离线增益和清醒回放（Bönstrup et al. 2019；Buch et al. 2021）；**清醒回放会给记忆打标记，供之后的睡眠优先巩固**（TINS 2025 综述）；但对长期记忆的更新，清醒休息的作用可能不如睡眠关键（Adv. Sci. 2026） | 短期 → 长期（候选） | **会话级整理**：把整场会话汇总成情节，产出蒸馏候选，原文复制归档并建立索引，给候选打上"待巩固"优先级；这一步不做跨会话的大规模重组 | 会话闲置超过阈值；会话结束 |
| **T3 睡眠** | 小时到天，离线 | **主动系统巩固**：NREM 期间慢振荡、纺锤波与涟漪相互耦合，海马回放逐步把内容整合进皮层，同时伴随全面的突触筛选（Lutz et al. 2025；Rasch & Born 2013）；**分工**：NREM 负责重激活和稳定，REM 负责精炼和整合〔综述〕；**重叠回放形成图式并带来洞察**（Lewis & Durrant 2011；Wagner et al. 2004）；**突触稳态**：整体下调，保留显著痕迹（Tononi & Cirelli 2014）；**图式加速**：符合已有图式的内容巩固得更快（Tse et al. 2007）；**记忆转化**：情景逐渐转成要点和语义（Winocur & Moscovitch 2011）；**选择性**：打过标记的、预期将来有用的记忆优先巩固（Wilhelm et al. 2011；Frey & Morris 1997）〔有争议：2021 年的复制研究未发现选择性增益〕；**定向重激活**（Rasch et al. 2007） | 长期 | **睡眠式离线整理**：①回放整合（对应 NREM：按标记排序，与已有知识一致的快速并入，冲突的需要更多证据或交给复核）→ ②关联与图式归纳（对应 REM：学习轨迹、模式、跨项目关联）→ ③全局降噪（对应突触稳态）→ ④验证后晋升；每轮可以用定向指令指定重点 | 每日；新增条目或冲突累积到阈值；空闲时 |
| **T4 提取时** | 任意时刻 | **再巩固**：被提取的记忆会暂时变得可修改（Nader et al. 2000）；**检索练习效应**：提取本身就会强化记忆（Roediger & Karpicke 2006） | 全层 | **用时再巩固**：召回并使用后，按"被证实 / 被推翻 / 被纠正 / 没用上"回写 | 每次召回后；用户纠正时 |

小结：工作记忆主要在 T0 整理（T1 时把子任务压成组块）；短期记忆在 T1 和 T2 整理；长期记忆在 T3 整理；T4 三层共有。

各时机之间前后衔接：T1 和 T2 打的标记，决定 T3 的回放顺序；T3 形成的图式，又能加快后续新情节的并入。

### 2.3 三层 × 五环节矩阵

表中编号见 §3 的人脑机制索引（M 编号）和 §5.3 的机制清单（P 编号）。

| 环节 | 短期记忆（全） | 工作记忆（专注与更新） | 长期记忆（精选、可唤起） |
|---|---|---|---|
| **编码** | 近期情景细节完整、逐字痕迹衰减快（M1）→ 原样记录全部经过，复制归档（P01、P02） | 门控（M3）→ 先判断与当前目标是否相关，再决定是否写入（P08） | 编码特异性（M9）、来源监控（M27）→ 沉淀时写入线索字段和来源类型（P15） |
| **维持** | 容量有限，会被驱逐或压缩 → 压缩前先抢救（P05） | 注意刷新；焦点约 4 个组块（M2、M4）→ 设预算，目标常驻（P07、P08） | 痕迹要能被激活才算"可及"（M9）→ 常驻线索层 + 可检索的归档（P03、P31） |
| **整理** | 事件边界回放（M6）→ T1 边界打包（P06）；清醒休息与打标记（M7）→ T2 会话级整理（P11） | 主动移除与组块（M3、M4）→ T0 即时整理（P08） | 系统巩固、分工、图式、稳态、图式加速、转化（M11–M17）→ T3：P16 → P17 → P18 → P21 |
| **提取** | 可按轮次、时间精确回读 → 回溯补全的首选来源（P04、P28） | 长时工作记忆、工作自我（M18、M19）→ 由工作记忆驱动唤起 | 线索唤起与模式补全、前瞻记忆与非自主记忆（M20–M24）→ 线索匹配浮现、情节补全（P24、P25）；元记忆（M25）→ 察觉不完整就回溯（P27、P28） |
| **遗忘** | 逐字细节衰减快（M1）→ agent 不必遗忘，原文永久归档，只是不再常驻 | 主动移除（M3）→ 过时内容立即移出工作记忆（原文仍在归档里） | 适应性遗忘、突触稳态、提取诱发遗忘、预测性遗忘（M14、M29–M31）→ 降低可及性，而不是删除原文（P18） |
| **全层** | ← 再巩固与检索练习（M26）→ T4 用时再巩固（P30） → | | |

### 2.5 借鉴人脑时的取舍

| 人脑特点 | 是否照搬 | 理由 |
|---|---|---|
| 逐字细节被迫遗忘 | 不照搬 | agent 可以永久保留原文，成本很低；遗忘在 agent 里等于"降低可及性" |
| 每天固定时长的睡眠 | 部分照搬 | agent 可以按需、并行地触发整理；但"与在线工作隔离、在离线时进行"这一点值得保留（Letta 在独立的 git 工作树里做反思，Codex 用独立的子 agent 整合） |
| 选择性巩固"预期有用"的记忆 | 作为可检验的假设 | 人脑中的证据不一致〔有争议〕，用消融实验来验证（§7.7） |
| 重构式回忆会走样 | 只取其利 | 用重构来补全和联想，但结果必须回到原文核实 |
| 容量极限约 4 个组块 | 照搬其精神 | 上下文虽大，注意力却会被稀释；工作记忆和常驻层都要设预算 |
| 情绪、奖励会调节巩固 | 转译 | 转成重要性标记：用户强调过的内容、决策节点、失败与纠正、未完成的承诺 |

### 2.6 归档策略〔已定〕

1. **复制归档，不依赖宿主的日志**。原因是宿主会清理自己的日志：Claude Code 默认只在本地保留会话记录 30 天，由 `cleanupPeriodDays` 设置〔官方〕。复制归档做好之前的临时措施：本机用户级的 `cleanupPeriodDays` 已于 2026-09-13 调为 3650。
2. **归档时对密钥、凭据、令牌等做脱敏，其余原样保留**。回忆从来用不到密钥，原样保留却会带来泄露风险。
3. **只存本地，永久保留**。遗忘默认只降低可及性，不删除原文。

4. **遗忘请求是 D1 的有条件例外**〔已定〕：用户明确要求"忘掉某段内容"时，允许改写原文归档，删除对应片段。条件有三：
   - 只在用户明确请求时执行；
   - 只删除指定的片段，不整会话连带删除；
   - 审计日志只记录"何时、依据哪次请求、删了哪个会话的哪些行"，不记录被删的内容。

   理由：隐私上的"被遗忘权"与"证据不丢"存在直接冲突，只能靠用户的显式授权来化解。这一例外需要在 AGENTS.md 的 D1 红线中注明，由用户修订。

## 3. 人脑记忆机制索引（M1–M33，按环节分组）

### 编码与短期层

| # | 机制（代表研究） | 要点 | 对 agent 的含义 |
|---|---|---|---|
| M1 | 近期情景记忆；逐字痕迹与要点痕迹（模糊痕迹理论，Brainerd & Reyna） | 刚经历的事细节完整；逐字痕迹衰减远快于要点 | 趁新鲜完整记录并尽早沉淀；原文永久归档 |
| M5 | 情景 / 语义 / 程序记忆（Tulving 1972；Squire 1992） | 语义从情景中抽象而来；程序记忆是"怎么做" | 按类型存储；语义层可以从情景层重新推导 |
| M6 | 事件分割与事件边界回放（Zacks et al. 2007；Ben-Yakov & Dudai 2011；Baldassano et al. 2017；Silva et al. 2019） | 人按事件切分经历；边界处快速回放并绑定成情景 | T1 边界打包；以事件为单位存储 |
| M9 | 编码特异性（Tulving & Thomson 1973）；线索依赖遗忘（Tulving 1974）；情境依赖记忆（Godden & Baddeley 1975） | 记忆存在不等于能取到；线索与编码时情境的重合度决定能否提取 | 写入时存线索；唤起时重建情境 |
| M27 | 来源监控（Johnson, Hashtroudi & Lindsay 1993） | 人会记错来源 | 记录来源类型和证据指针 |

### 工作记忆层

| # | 机制（代表研究） | 要点 | 对 agent 的含义 |
|---|---|---|---|
| M2 | 多成分工作记忆（Baddeley 2000）；嵌入加工模型（Cowan 1999、2001） | 工作记忆 = 被激活的长期记忆 + 注意焦点；焦点约 4 个组块 | 设预算；长期记忆靠"激活进工作记忆"来发挥作用 |
| M3 | 更新与主动移除（Ecker et al. 2014；Oberauer 2018）；门控（PBWM） | 更新 = 移除 + 编码；移除是主动的、按条目进行的 | T0：用替换代替追加，主动移除，按目标门控 |
| M4 | 注意刷新（TBRS）；组块（Miller 1956） | 利用注意力间隙刷新；把多项压成一个单元 | 目标常驻；把完成的子任务压成组块 |
| M18 | 长时工作记忆（Ericsson & Kintsch 1995） | 专注执行任务时，靠提取结构调用长期知识 | 由工作记忆驱动唤起 |
| M19 | 自我记忆系统（Conway & Pleydell-Pearce 2000） | 自传知识分层；工作自我的目标控制提取 | 分层组织；用当前目标筛选召回结果 |

### 整理与巩固

| # | 机制（代表研究） | 要点 | 对 agent 的含义 |
|---|---|---|---|
| M7 | 清醒休息巩固与清醒回放（Dewar et al. 2012；Tambini et al. 2010；Bönstrup et al. 2019；Buch et al. 2021；TINS 2025） | 短暂休息就能增强记忆；清醒回放为之后的睡眠巩固打标记 | T2 会话级整理 + 打标记 |
| M8 | 互补学习系统（McClelland, McNaughton & O'Reilly 1995） | 海马快速记录，新皮层慢速提炼 | 在线阶段快而保真地写；离线阶段慢慢抽象 |
| M10 | 睡眠巩固总论（Diekelmann & Born 2010） | 睡眠中选择性回放并整合 | 设置离线的"做梦"阶段 |
| M11 | 主动系统巩固（Rasch & Born 2013；Lutz et al. 2025） | NREM 期间多种振荡耦合，驱动回放和迁移，伴随突触筛选 | T3① 回放整合 |
| M12 | NREM 与 REM 的分工〔综述〕 | NREM 负责重激活和稳定；REM 负责精炼和整合 | T3 分成整合、归纳两步 |
| M13 | 重叠回放形成图式；睡眠带来洞察（Lewis & Durrant 2011；Wagner et al. 2004） | 反复出现的共同成分在回放中被强化 | T3② 关联与图式归纳 |
| M14 | 突触稳态假说（Tononi & Cirelli 2014） | 整体下调，保留显著的痕迹 | T3③ 全局降噪 |
| M15 | 图式加速巩固（Tse et al. 2007） | 符合已有图式的内容巩固得更快 | 与已有知识一致的快速并入，冲突的要求更多证据 |
| M16 | 记忆转化与多重痕迹（Nadel & Moscovitch 1997；Winocur & Moscovitch 2011） | 情景逐渐转成要点，细节依赖海马；两种形式可以并存 | 要点层与原文层并存，并相互链接 |
| M17 | 标记与选择性巩固（Frey & Morris 1997；Wilhelm et al. 2011）〔有争议〕 | 打过标记的、预期有用的记忆优先巩固 | T1、T2 打标记，T3 按标记排序；需要实证检验 |
| M28 | 定向记忆重激活（Rasch et al. 2007） | 睡眠中给出线索，可以定向加强某些记忆 | 用定向指令控制整理的重点 |
| M26 | 再巩固（Nader et al. 2000）；检索练习（Roediger & Karpicke 2006） | 提取后记忆暂时可改；提取本身会强化记忆 | T4 用时再巩固 |

### 提取与唤起

| # | 机制（代表研究） | 要点 | 对 agent 的含义 |
|---|---|---|---|
| M20 | 模式补全（海马 CA3；Marr 1971）；扩散激活（Collins & Loftus 1975） | 部分线索就能补全整段记忆 | 唤起的是整段情节，不是碎片 |

| M22 | 非自主自传记忆（Berntsen 1996、2010） | 当前情境与过去经历特征重合度高时，记忆会不请自来 | 每轮做低成本的线索匹配，超过阈值才浮现 |

## 5. 能力维度与机制清单〔已定：两层分离〕

**分离的原则**：
- **能力**是"用户能感知到的结果"，是评测对象，与需求 R1–R14 一一对应；

## 6. 理想目标

### 6.1 北极星：一位共事多年、记性好又靠谱的同事

1. **手头的事全记得**：上下文被压缩了也不丢。（K1）
2. **清楚自己在做什么**：状态一变就更新，被打断后能接着做，隔天也能接上。（K2）
3. **分时整理**：做事时随手更新手头状态；一件事做完就打包归档；会话结束时做汇总、打标记；在"睡眠"中融会贯通、清理噪声；每次用到一条记忆时就强化或修正它。（机制 P06、P08、P11、P16–P18、P30）
4. **不用你说"记住"**：重要的沉淀下来，其余的完整存档。（K3）
5. **记得前因后果和当前状态**，知道哪些已经过时。（K5）
6. **在相关的时刻自然想起，而且想得完整**；把握不大时宁可不说。（K6、K7、K8）
7. **只记得大概时，知道自己只记得大概**：先翻记录；事关重大或补不全时，复述给你确认。（K9、K10）
8. **引用记忆时说明来源、日期和可能过时之处**，查不到就说没有，不会被"洗脑"。（K12）
9. **踩过的坑不再踩，被纠正过的不再犯。**（K11）
10. **换一个 agent 还是同一个"它"，而且越用越好**，好在哪里有评测可以证明。（K13、Q3）

### 6.2 成熟度判定标准〔已定：按标准判定，实测后填写〕

每个能力维度按"**支撑机制是否具备** + **指标是否达到门槛**"来评级。门槛等基线实测后，由用户确认后写入评测契约。

| 等级 | 机制条件 | 指标条件 |
|---|---|---|
| L0 | 没有任何支撑机制 | 不优于无记忆基线 |
| L1 | 有基础机制，如存取、检索 | 显著优于无记忆基线 |
| L2 | 有结构化机制，如类型、对账、作用域、工作记忆、会话级整理 | 显著优于朴素 RAG 基线（在原始轮次上做 RAG） |
| L3 | 有该能力对应的分时整理或主动机制，而且各时机之间衔接 | 达到门槛 X（待定），消融实验证明关键机制确有贡献 |
| L4 | 策略可学习、可进化 | 跨版本持续提升，并且可以回滚 |

### 6.2a L3 门槛 X〔已定：2026-09-25 用户批准〕

L3 的"门槛 X"是一组**全部满足才成立**的条件，不是单个分数。机器可读副本：`docs/research/benchmark-suite/thresholds-l3.yaml`（两处不一致时以本节为准）。门槛在看到下一轮读数**之前**写定；改门槛视同改评测契约，只能由用户决定，不能为某次读数回头调。

### 6.3 设计原则

1. **短期求全，工作求专，长期求精。**
2. **整理贯穿三层、分时进行**：前一个时机打的标记，服务于后一个时机的优先级。
3. **证据不丢，抽象可以重建**：原文复制归档、对密钥脱敏、永久保存；遗忘就是降低可及性。
4. **要点常驻，细节可以回溯。**
5. **在专注中调用长期记忆**：由工作记忆驱动唤起。
6. **主动但克制**：线索触发为主，精确率优先，宁可少说。
7. **唤起要完整**：从碎片补全成情节，再回到证据核实。
8. **拿不准就查，查了还拿不准就问**；无人值守时写入待确认队列。
9. **时间是一等公民。**
10. **离线整理与在线工作隔离**，每次整理都可以验证、可以回滚。
11. **默认怀疑记忆的内容**：记忆是数据，不是指令。
12. **借鉴人脑要有取舍**：有争议的机制只作为假设，用实验验证。
13. **能力靠评测证明，机制靠消融证明**；先跑简单基线。

## 7. 评价体系

### 7.1 借鉴 AML，补上它的盲区

**值得照搬的做法**〔官方〕：
- 被测系统只提供 Add 和 Search 两个接口，其余环节都固定；
- 按能力项给出分数画像（文本类 7 项、coding 类 2 项）；
- 评测契约有版本；
- 用按时间切分的真实数据；
- 有强基线（开源榜前三都是简单方案）。

**AML 的盲区**：它只测"长期记忆被问到时能不能取到"，测不到 K1、K2、K7、K8、K9、K10、K13，也测不到机制本身的作用。

Always-On Agents 综述还指出，现有文献偏重"积累和检索状态"，忽视了"治理、恢复和放弃状态"。它提出的 AOEP 协议评的是状态变更与恢复义务，本体系在 K12 和 Q2 上借鉴这一点。

### 7.2 评测原则

1. **固定答题器**〔已定〕：行为级评测使用仓库内可控的 harness（LangGraph + 固定版本的模型，通过兼容 OpenAI 的接口调用），保证可复现、成本可控。评委与答题器用不同的模型，互相审查（沿用现有的 `AGENT_MEMORY_JUDGE_*` 配置）。真实宿主（kimi、Claude、Codex）只做抽检。
2. **给出能力画像**（K1–K13），同时报告系统约束 Q1–Q3。
3. **强基线必跑**：无记忆 / 全上下文（放得下时）/ 朴素 RAG（在原始轮次上）/ 可选的商用系统（只在不涉密的数据上跑）。
4. 配对统计（McNemar 检验、bootstrap）；样本少于 20 条时标注"不足以下强结论"。
5. 评测契约要有版本；评测集和门槛不允许 agent 修改（D6），产出流程见 §7.9。
6. 同时报告质量、成本、延迟。
7. 真实数据按时间切分；合成数据和真实数据分开报告。
8. **机制用消融来评**（§7.7）。

| 全局（线上） | **用户纠正次数**（"你记错了""我说过……"）；召回被采纳的比例；语义漂移 | D | 统计真实会话日志 |

### 7.4 专项一：主动联想与线索唤起（K7、K8，兼顾 K6）

**设置**：若干带日期的历史会话，加一个触发会话。在触发会话中，用户在做另一件事，**并没有问任何关于记忆的问题**。

| 类型 | 例子 | 期望 |
|---|---|---|
| 应联想 | 昨天学了 GloVe，今天问 word2vec 的负采样；证书 9/15 到期，今天要准备 9/20 的发布 | 在前 N 轮内主动、正确地关联上 |
| 线索间接 | 线索与原文的字面不重合 | 仍然能被唤起 |
| 不应联想 | 表面相似，其实无关 | 保持沉默 |
| 时间陷阱 | 相关记忆已被取代 | 只浮现最新状态，或者说明"已变更" |

**比例**：2 : 1 : 2 : 1。

**主指标**：**F0.5** = (1 + 0.5²)·P·R / (0.5²·P + R)，其中 P 为浮现精确率，R 为主动召回率〔已定：精确率优先〕。

**辅助指标**：过时浮现率、首次浮现轮次、打扰感、唤起完整度。

### 7.5 专项二：完整性自知与理解对齐（K9、K10）

**设置**：历史中有一段信息量很大的内容（比如一次交代了 8 条要求的任务），长期记忆里只有它的要点，完整原文在归档中。

| 类型 | 设置 | 期望行为 |
|---|---|---|
| 需要补全 | 任务依赖某条只在原文里的细节 | 察觉 → 回溯 → 补全后再做 |
| 要点足够 | 只需要框架层面的信息 | 直接做，不去查 |
| 需要确认 | 要求有歧义、事关重大，或者补不全 | 复述理解，请用户确认 |
| 不必确认 | 低风险、信息明确 | 不打扰 |
| 无人值守 | 同"需要确认"，但当前没有用户在场 | 写入待确认队列，同时继续做不依赖该确认的部分，或者安全地暂停 |
| 记错陷阱 | 要点与原文有细微出入 | 回到原文后纠正 |

**指标**：
- 不完整察觉率；
- 回溯补全成功率；
- 过度回溯率（以及回溯的成本）；
- 确认的 F0.5〔已定〕；
- 复述准确度；
- 正确入队的比例；
- 完整度校准。

### 7.6 专项三：工作记忆与当下保真（K2、K1）

在长任务中随机打断，询问当前的目标、已完成的部分、下一步、未决问题、关键约束，与真实状态逐字段比对。需要覆盖以下几种情形：
- 压缩之后；
- 切换任务再回来之后；
- 跨会话之后；
- 状态刚发生变化之后；
- 在同一项目中并行多个任务时（检验按任务划分之后，状态是否会互相串）。

指标见 §7.3 中 K1、K2 两行。

### 7.7 专项四：机制有效性（消融实验，类似"剥夺睡眠"实验）

对同一批历史数据跑同一套评测，分别关闭某个机制或整理时机，观察各项能力的变化。**机制是否有价值，由这组实验来回答。**

## 8. agent-memory 现状初评（按能力；仅供参考，实测后按 §6.2 的标准判定）

| 能力 | 初评 | 依据〔实测〕 | 主要差距 |
|---|---|---|---|
| K1 当下保真 | L2 | 6 个宿主日志读取器；可按轮次回读 | 没有压缩前抢救和事件边界打包；宿主日志会被清理（Claude Code 默认 30 天），而归档只在会话收尾时发生 |

**小结**：
- **强项**：治理、更新一致性、可靠性、跨会话续接。
- **核心短板**：K7、K8、K9、K10，外加两个机制缺口：T1 事件边界整理和 T3 归纳。
- **实测发现的两个隐患**：归档没有脱敏；宿主日志会被清理，而归档只在会话收尾时才发生。这两点在优化时应最先处理。

## 8a. v0.5 补充：两处指标缺口（2026-09-22，由外部验收失分反推）

不改动上面任何〔已定〕内容；这里只补指标。缺口是在 PersonaMem 验收（v1 45 vs 朴素 RAG 53，p=0.039）的失分分析里暴露的：失分能归到能力，却对不上任何一个既有指标，说明标准本身测不到这类失分。

| 能力 | 失分形态 | 既有指标为什么测不到 | 新增指标（离线，A/B 层） |
|---|---|---|---|
| **K11 个性化** | 记忆里明明有用户说过的偏好/事实，回复却选了"不提任何记忆的通用回复"——**有记忆而不用** | "个性化得分"只评回复合不合偏好，没有区分"用错了"和"没用"；线上层的"召回被采纳的比例"（D 层）离线没有对应物。K8/K10 的"精确率优先、宁可少说"只针对**主动插话与确认**，不应外溢到"用户自己提起的话题" | **记忆采纳率**：选择题形式，用户随口一句话触及某条记得的事实，候选回复含一个用对了的、一个不提记忆的通用回复、若干记错的；指标 = 选中"用对了"的比例。通用回复被选中即计为"有记忆而不用" |
| **K4 精确回忆** | 问答分数低于朴素 RAG，但 recall@k 看不出差别（两者证据会话召回都 100%） | recall@k 按"证据会话是否出现"算，粒度太粗；载荷里**哪些原话**到了、体量多大，没有指标 | **检索对等率**（A 层，不调 LLM）：朴素 RAG 前 k 条原话中也出现在被测系统载荷里的比例，目标 ≥ 90%；**载荷体量比**（Q1）：被测载荷字符数 / 朴素 RAG 载荷字符数，目标 ≤ 1.15（靠多塞上下文赢不算赢） |
| **K5 时间与变化** | 用户改了偏好/安排/取值，之后问"当初为什么改"，记忆里只剩"从 X 变成了 Y"，原因没了（PersonaMem `recalling_the_reasons_behind_previous_updates` 4/6） | K5 的定义含"因果"，指标却只有更新正确率、时态、截至某时、过时识别——**变更的原因**没有指标；蒸馏/整理把变更压成取值差，原因是最先被磨掉的部分 | **变更原因保留率**（A/B 层）：对话里给了变更原因的，问"为什么改"时原因到场并被答出的比例 |

| **K12 可信与安全（查不到就说没有）** | 题面点名的东西与记忆里某个东西**字面相近、实为两物**（问 table tennis，记忆里是 tennis；问 Software Engineer Manager，记忆里是 Senior Software Engineer），答题器拿近形实体的值作答（LongMemEval knowledge-update `_abs` 2/2 失分，朴素 RAG 同错） | "拒答正确率"不分前提与记忆的距离：无关实体、同类异物、字面近形变体三类难度差异很大，验证集只覆盖了前两类，于是验证集满分、测试集失分；且没有对偶的护栏指标，单独追拒答率会把可答题带成错误弃答 | **近形前提识别率**（A/B 层，按距离分层报告：无关 / 同类异物 / 字面近形）+ **错误弃答率**护栏（换了说法但确属同一事物的可答题被拒答的比例，目标 0）。两者同时报告，任何一个变差即否决 |

| **K8 主动回忆时机 / K13 跨 agent 连续（系统层）** | 当前仓库记下的约定（开发端口、测试命令、迁移方式），用户在该仓库里发出直接受它约束的请求，却时而浮现、时而沉默（MemCompass xa/S 同一输入副手 5 次里只浮现 1 次；v0.2.2 与 v0.3.1 的 10/12 对 5/12 基本是单次采样的运气） | F0.5 与注入成功率都按单次采样计，测不到"同一输入是否总是同一决定"；评测缓存又把单次采样固化成定值，版本对比会把采样噪声读成退步 | **浮现一致性**（A/C 层）：同一输入不走缓存重复 N 次（N≥5），决定一致的比例；作用域内约束类的正例目标为 100%。与负例误插话率同时报告 |

| **K9 完整性自知（口径修正）** | memory-v1 的检索结果每一束都带原话，"只有要点"的状态不再出现；MemCompass ca/E 的"不完整察觉率"却只认 v0.2 的 `<raw_evidence>` 标签，把 v1 读成 50%（同一批题补全成功率 100%）。同一个"含系统附带原文"的口径还被用在护栏"过度回溯率"上 | 指标绑定了某一版的载荷格式；护栏量的本应是答题器多余的动作，却把系统随检索附带的原文也算进去 | **不完整察觉率**：需要细节的题里，细节是否到场（答题器主动调原文工具，或系统随检索附带了原文——认 `<raw_evidence>` 与证据束里的原话两种形态）。**过度回溯率**（护栏）：只算答题器主动调原文工具。源头 runner 已改（`benchmark-suite/runners/mc_run.py` `_carries_raw`、`mc_report.py`），冻结副本待用户迁入；t4 读数按新口径离线重算：察觉率 v1 12/12、v0.2.2 12/12、朴素 RAG 12/12，过度回溯 v1 2/8、v0.2.2 4/8、朴素 RAG 7/8 |

（K12 一行 2026-09-23 补，由 LongMemEval 验收失分反推；K8/K13 一行 2026-09-25 补，由 MemCompass 回归反推；K9 口径修正 2026-09-25 补，由 MemCompass 回归复查。）

这两项与 §6.2 的 L2 判据（显著优于朴素 RAG）配套：检索对等率是"不低于朴素 RAG"的前置条件，记忆采纳率是"高于朴素 RAG"要靠的那部分能力。
