## 0. 目标的可操作定义（来自框架 §6.2）

成熟度标准已经把"强"定义好了，直接用它，不另立口径：

| 等级 | 指标条件 | 本设计的目标 |
|---|---|---|
| L2 | **显著优于朴素 RAG 基线** | **K1–K13 每一项**都要达到（现状：只有 K12 与 K2/K8/K13 的系统层达到） |
| L3 | 达到门槛，且消融证明关键机制确有贡献 | ★ 核心诉求 K1、K2、K7–K10 |

"显著优于"按框架 §7.2：配对统计（McNemar / bootstrap），n<20 不下结论。
"全面"的含义：按能力、按题型分桶，**没有任何一桶低于对照组中最好的那个**（朴素 RAG / 全文上下文 / 无记忆）。总分持平会掩盖"此处赢 4、彼处赔 7"。

## 1. 从评价标准反推：分数由什么决定

框架 §7.3 的四层评测，决定了机制要满足的四个函数形态：

| 评测层 | 形态 | 得分 = | 对机制的要求 |
|---|---|---|---|
| A 组件级 | 逐环节度量 | 抽取/检索/更新/拦截各自正确率 | 每个环节可单独度量、可消融 |
| B 问答级（AML 式：Add → Search → 固定答题器 → 固定评委） | 记忆系统只控制 Search 返回什么 | P(证据进载荷) × P(答题器用对 ∣ 载荷) | **载荷的信息量不得少于任何对照组；载荷的组织要让答题器更容易用对** |
| C 行为级 | agent 实跑 | 对的时刻拿到对的东西（状态、浮现、完整度） | 状态层与触发是一等机制 |
| D 运行级 | 长期使用 | 纠正率、漂移、成本 | 读路径便宜、可回滚 |

B 层那一行是全稿的支点。现有数据〔实测，附录 A〕：LongMemEval n=60 上 am 与朴素 RAG **证据召回都是 60/60**，正确率都是 46/60——**P(证据进载荷) 已经饱和，丢分全在 P(用对 ∣ 载荷)**。所以往检索上堆机制（v0.4 的方向）不可能提分；能提分的只有"载荷里放什么、怎么组织"。

## 2. 三条原则

**原则一：证据是值，记忆是键和注解。**（框架 §6.3 第 3、4、7 条："证据不丢，抽象可以重建""要点常驻，细节可以回溯""唤起要完整：从碎片补全成情节，再回到证据核实"）
原文归档是唯一的值存储。蒸馏出的一切（论断、线索、时间、画像、教训、状态）只有两种身份：通向证据的**键**，附在证据上的**注解**。检索返回的单元是**证据束** = 注解 + 它指向的原话。
→ 任何问答集上，答题器看到的信息 ⊇ 朴素 RAG 给的信息——由返回单元的定义保证，不靠事后补丁。

**原则二：只组织，不裁决。**（§6.3 第 11 条："默认怀疑记忆的内容"；第 6 条："主动但克制"）
读取期记忆层不产出结论——不说"不存在"、不说"共 N 个"。只做确定性的组织：归并、排序、标日期、标取代、标出处。结论由答题器面对证据得出。一条错的论断不会"只是没帮上忙"，它会**否决**旁边的正确证据（附录 A：v0.4 因此赢 4 题赔 7 题）。
→ 读路径零 LLM（同时满足 Q1）；不存在"默认关闭"的机制。

**原则三：智能前移到写入与离线整理，只增不减。**（§6.3 第 2、10 条：分时整理；离线隔离）
写入期与 T3 可以花 LLM：抽论断、落绝对时间、生成线索键、维护取代链、归纳。产物永远是**加**在证据上的键与注解。蒸馏漏了或错了，代价上限是"少一个键"，不是"丢一个事实"。

## 4. 机制（七个，每个服务多项能力）

**M1 单一读路径 `recall` + 证据束**（K1、K3、K4、K7、K9、K12、K13、Q1）
```
recall(query, scopes, k)
  记忆路：混合检索命中论断 ─┐  按证据位置 (source, session, line) 归并成证据束；
  原文路：混合检索命中原话 ─┘  同一处证据被两路命中 → 名次贡献相加（等权 RRF）
  过滤：原文行过 gate.check_instructional；scope 在 SQL 层过滤；已遗忘片段在原文层已擦除
  渲染：[日期] 论断（含取代史）｜原话摘录      纯原文束：[日期 角色] 原话
```
`memory_search`、`memory_context`、AML Search、全部评测 runner 走这一条路。取代 P23 启发式回退、P35 交错、`search`/`aml_search` 分叉；P34/P36b/P37 不进本分支。

**M2 写入期时间落地**（K5、K8）：蒸馏 schema 增加 `event_date`——把"上周二""三周前"按会话日期解析成绝对日期；保留既有双时态与取代链。束按事件日期标注。

**M3 写入期线索键**（K6、K7、K8）：每条论断带 `cues`（实体、别名、上位类、情境特征），进索引作为**额外的键**指向同一处证据。问"几个鱼缸"时，上位类键把散在各会话的实例证据一起拉到前排——提高的是"全部证据到场"的概率，不替答题器数数。

**M4 状态层**（K1、K2、K8，现有，保持）：按任务的工作记忆、会话开头注入、压缩前抢救；`recall` 接受状态（目标、未决问题）作为附加查询路（§6.3 第 5 条"由工作记忆驱动唤起"）。

**M5 离线整理产出新键**（K6、K11，T3）：归纳出的图式、教训、画像同样是"键 + 注解 + 证据指针"；只写复核队列（与 D6 相容）。

**M6 治理**（K12、K13，现有，保持）：评价门、遗忘（原文擦除）、作用域、复核队列、快照回滚。

**M7 行为协议**（K10、K12）：SKILL 指引里的引用来源、何时确认、证据不足时怎么说——基于束上的注解（日期、出处类型、冲突标记），不靠读取期 LLM。

## 6. 准入纪律（防再次过拟合）

1. **一套默认配置跑全部评测**，不为任何评测集设开关或参数。
2. 一个机制进主干：在**至少两个互相独立来源的评测**上配对比较同向不劣、至少一个显著更优；**任何一桶显著变差即否决**。
3. 每阶段先写可证伪预测再跑。
4. 读路径出现 LLM 调用、或出现默认关闭的机制 = 设计违规。
